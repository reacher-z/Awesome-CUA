Methods: from interface grounding to learning through interaction

The central methodological question is how an agent's observation, action interface, training data, and learning objective determine what transfers to a new task. Generalization has several meanings here: locating unfamiliar controls, composing familiar operations into a new workflow, recovering from an unexpected state, or moving between operating systems. A method can improve one without establishing the others. We therefore compare systems by the information and control they receive, the experience they reuse, and the feedback that changes their behavior. This separates architectural mechanisms from reported benchmark outcomes, which often use different histories, tools, evaluators, and interaction budgets.

Observation and grounding define the control problem

Structured interface representations make some decisions easier by exposing labels, hierarchy, and actionable objects directly. Mind2Web's baseline first ranks DOM elements, then selects an element and operation from reduced candidate groups. This makes large pages manageable, but the pruning stage creates a recall boundary: downstream reasoning cannot select a target that was removed. SeeAct separates screenshot-based action description from grounding that description to an executable element. Its experiments distinguish textual choices, visual marks, and human oracle grounding. That separation is diagnostically useful: knowing what should happen and identifying where to act are different capabilities, and oracle grounding does not demonstrate autonomous execution.

The label “visual agent” does not uniquely specify the observation contract. WebVoyager uses screenshots annotated with interactive elements obtained through JavaScript, together with auxiliary element text. AppAgent's Android implementation uses XML-derived identifiers and numbered screenshot overlays. Mobile-Agent instead combines optical character recognition (OCR), icon detection, and visual matching to localize actions without XML. These choices exchange structural coverage for perceptual estimation: a missing accessibility node and a misrecognized icon fail differently. Mobile-Agent's experiments are on Android even though the interface motivates broader portability. Cross-platform intent should therefore be distinguished from platforms actually evaluated.

Coordinate-based grounding models predict locations directly, but they still make representation choices. SeeClick trains coordinate-text prediction using GUI grounding and inverse OCR tasks. CogAgent supplements a conventional visual path with a higher-resolution cross-attention module, addressing small text and controls without placing all high-resolution features in one self-attention sequence. UGround separates a screenshot planner from a specialized visual grounder and adapts image resolution for interface localization. These approaches make coordinate prediction trainable, while retaining a practical trade-off between spatial detail and processing cost. Better localization alone does not resolve an incorrect instruction from the planner; Aria-UI explicitly identifies that dependency as a limitation.

Visual deployment also should not be confused with structure-free training. CogAgent, SeeClick, and UGround use structured web information to construct visual supervision. OS-ATLAS extends collection through platform-specific accessibility APIs and exploration, then separates grounding pretraining from action fine-tuning. Thus, structure can serve as a training instrument even when it is absent at inference. The transfer question becomes whether the resulting visual representations cover unfamiliar controls and referring expressions, rather than whether HTML was ever used. Conversely, a shared action schema is an interface convention: standardizing click, tap, and scroll labels does not make their platform-specific effects identical.

ShowUI treats visual efficiency as part of grounding. It groups neighboring patches with similar pixel values and skips selected redundant tokens while preserving the positions of retained tokens. It also interleaves screenshots and actions for navigation, and packs multiple grounding queries against one screenshot during training. Aria-UI adds task and action history to grounding examples, including interleaved visual context. Together, these designs show why neither resolution nor context length is a sufficient description of perception: the agent must retain the small spatial cues and earlier states that matter to the current decision. Compression quality should be evaluated against that decision, not only token savings.

Modular control, native policies, and hybrid execution

Modular systems allocate different responsibilities to different components. UFO's HostAgent selects applications and coordinates work, while an AppAgent operates application controls through Windows automation. Agent S separates a manager's task decomposition from workers' grounded execution and reflection. Its interface augments an accessibility tree with OCR and restricts execution to discrete actions with feedback after each step. These decompositions provide explicit places to diagnose planning, grounding, and execution failures. They also introduce dependencies: UFO cannot operate controls unsupported by its backend, and Agent S's original interface requires more than pixels. Hierarchy organizes those dependencies; it does not eliminate them.

Native policies move more of this coordination into a trained model. Aguvis trains grounding before planning and reasoning, representing actions through PyAutoGUI-style commands plus platform-specific extensions. UI-TARS predicts reasoning and actions from screenshots and interaction history, with shared and device-specific actions and an explicit request for user intervention. This reduces the need to hand-specify every intermediate module, but execution still depends on an external action interpreter and environment. A unified output format also cannot guarantee semantic compatibility: typing into a focused field, selecting an object, and terminating a task require different state conditions even when their commands share one syntax.

The practical boundary is increasingly hybrid. Agent S2 routes actions to visual, OCR-based text-span, or structural specialists; its spreadsheet specialist can update cells programmatically. UFO2 combines Windows UI Automation and visual detections, then prefers registered native application APIs with GUI fallback. UI-TARS-2 extends GUI control with terminal and other tool operations in shared stateful environments. These are substantive changes to the available action space, not interchangeable implementations of a pointer-only agent. They can shorten workflows by expressing structured operations directly, while introducing application bindings, tool permissions, and backend-specific failure modes. Comparisons should state which routes were available and which actually executed.

Jev-Mobile examines a different division of labor: a vision-language model (VLM) sets a local goal and exact input text, while a typed decision service chooses from actions enumerated from the current Android accessibility tree. Candidates are rebuilt after each action, so delegated execution retains feedback rather than replaying an unobserved batch. Typed output constrains the available choices but does not establish that a chosen action is correct. Tree-missing visual targets remain inaccessible, and “local” denotes decision scope rather than on-device inference. Its comparison evaluates complete systems with different executors; it does not isolate a causal advantage of the decision model over a small VLM in the same controller.

Planning, memory, verification, and recovery

A history is not yet a useful state representation. AppAgent turns exploration or demonstrations into documents about application behavior. Agent Workflow Memory extracts reusable subroutines and replaces example-specific values with variables; its offline and online variants differ in when those workflows are acquired. Agent S retrieves high-level narrative experience for planning and more concrete episodic experience for workers. These mechanisms reuse experience without necessarily updating model weights. Their evaluation must specify what memory exists initially, whether it grows across test tasks, and how experiences are admitted. In the online variants, model-based success judgments can propagate mistakes into later retrieval.

Memory can also be learned as a control policy. MementoGUI trains operators for selecting salient events, compressing working memory, writing episodes, and filtering retrieval results. It preserves selected image regions alongside textual summaries and augments a frozen GUI action model. This distinguishes learning what to remember from fine-tuning how to act. However, its reported evaluations use offline GUI benchmarks and model-judged action or memory measures; they should not be read as proof of live task completion. The broader design issue is evidence preservation: compression can discard a transient selection or dialog state that is unavailable in the current screenshot.

Structured planning introduces stronger internal constraints, with correspondingly stronger modeling assumptions. Agent+P builds a UI transition graph using static program analysis and dynamic refinement, translates navigation into a symbolic planning problem, and sends the plan to a UI executor. Its formal guarantees apply to the represented graph and chosen target, not automatically to the real application or the interpretation of user intent. ActionEngine instead learns application states and reusable operations through offline exploration, then compiles a generated program into browser actions and data operations. Both shift work from repeated local deliberation to reusable application knowledge; incomplete graphs, changed controls, and mistaken state identification remain operational concerns.

Verification operates at several levels that should remain separate. Mobile-Agent reflects on unchanged or unexpected screens. Agent S can return failure to its manager, and Agent S2 revises the remaining plan after subgoals. Such checks can guide recovery without independently proving that the user's goal was achieved. A visible draft is not necessarily a saved document, and a model's completion token is not an external state check. Likewise, success judgments used to filter training trajectories need their own validation. The methodological distinction is between detecting a suspicious transition, choosing a corrective action, and establishing the final postcondition.

Recovery becomes more concrete when training includes states reached after mistakes. UI-TARS annotates both a corrected action at the error point and a subsequent correction after the wrong action has already changed the environment. OpenCUA allows imperfect human demonstrations, uses a reflector to identify incorrect or redundant steps, and constructs reasoning around state transitions while excluding unsuitable action targets from training. These recipes address a gap in clean demonstrations: an agent deployed on its own predictions visits states that an expert path may never contain. Reflection text is useful supervision, but its presence does not establish that the generated explanation faithfully causes the action.

What the data teaches, and what collection leaves out

Grounding data and trajectory data supervise different problems. Element descriptions paired with coordinates teach localization; a sequence conditioned on a user goal teaches when and why an action is useful. OS-ATLAS and Aguvis make this distinction explicit through staged training. The referring-expression distribution matters too: functional descriptions, spatial relationships, and visual appearance ask different questions of the same control. UGround and Aria-UI synthesize such variation instead of relying only on literal element text. Scaling annotation count can therefore leave important gaps if most examples repeat easy labels, shallow pages, or one interaction style.

Human demonstration pipelines must reconstruct decision-time information carefully. OpenCUA records screen video and input signals, compresses low-level events into meaningful actions, and aligns actions to prior screen states. For clicks, it searches before cursor movement to reduce leakage from a pointer already indicating the target. This illustrates a general issue in offline training: the recorded observation must contain information available before the decision. Action reduction also chooses the temporal unit of learning. A merged scroll or text insertion is easier to model than thousands of device events, but exposes different opportunities for intermediate feedback.

Synthetic trajectories differ mainly in where their goals come from. AgentTrek filters and standardizes tutorials, then uses a browser agent to replay their instructions and a model to judge the resulting trajectories. Explorer refines a task while navigating, allowing the eventual instruction to reflect what is actually available. OS-Genesis starts from observed action transitions, infers plausible low- and high-level tasks, and subsequently executes those tasks. These approaches reduce dependence on manually recorded demonstrations, but select different experience distributions: published procedures, goals consistent with an exploration path, or functions discovered through traversal. None establishes exhaustive coverage of realistic user intentions.

Filtering determines what the model is allowed to learn from. Explorer halts collection at login, CAPTCHA, and payment boundaries, which limits the resulting workflows. AgentTrek's replay uses structured browser observations even when the resulting data later trains a visual policy. OS-Genesis uses graded trajectory scores to sample some incomplete but informative executions rather than keeping only binary successes. These choices should be reported alongside dataset size. Our synthesis is that diversity has at least three dimensions: interface coverage, goal coverage, and state coverage after errors. A large corpus can be broad in one dimension while remaining narrow in the others.

Generated reasoning adds another supervisory layer. Aguvis constructs inner monologue using the goal, observation, history, and known action. UI-TARS explicitly recognizes the risk of explanations that merely fit a supplied answer and also samples thought–action pairs before selecting those that match the target. OpenCUA adds reflection, memory, and planning information through a multi-stage synthesis pipeline. These are methods for constructing useful training targets, not direct recordings of human reasoning or demonstrations of causal faithfulness. Their value should be assessed through controlled ablations and behavior on unfamiliar states, with the generator and filtering policy treated as part of the data recipe.

Objectives determine which errors receive feedback

Supervised fine-tuning, preference optimization, and reinforcement learning should not be grouped solely by whether a paper uses the word “reasoning.” Supervised learning increases the likelihood of demonstrated outputs. UI-TARS's preference stage additionally contrasts corrected and erroneous actions. GUI-R1 applies group-relative optimization to candidate responses using format, action-type, point-in-box, and input-text rewards. These rewards verify an annotated local prediction; they do not by themselves measure whether a freely executed multi-step task succeeds. Local action accuracy can improve while delayed consequences and recovery remain outside the training signal.

Reward granularity determines which mistakes the learner can distinguish. A point inside the annotated box establishes a localization match, but does not check whether the application accepted the operation or retained the intended change. Conversely, a final success label does not identify which intermediate actions were necessary. In successful-rollout filtering, actions along a retained path receive imitation supervision even when some were redundant. Preference pairs can target a known mistake more precisely, but their coverage is limited to the states and alternatives collected. These are complementary sources of information rather than a universal ordering of objectives. A transfer claim is stronger when evaluation tests both unfamiliar successful paths and the error states that the chosen supervision leaves weakly constrained.

Environment-interacting RL exposes those consequences but must solve reward and credit-assignment problems. WebRL generates curriculum tasks from failed attempts, evaluates outcomes with a learned reward model, and constrains policy updates while retaining replay experience. Its policy observes HTML and history, and its outcome model uses the final page plus actions. UI-TARS-2 trains multi-turn policies with stateful rollouts, using different reward mechanisms for different domains: executable checks, answer judges, or generative outcome scoring. A result described as “verifiable” must therefore specify what is checked and by whom. A learned judge is a useful source of supervision, not an automatic guarantee of goal correctness.

The interaction horizon changes both learning difficulty and the behaviors an agent can express. Test-Time Interaction (TTI) studies a curriculum that progressively permits longer rollouts, using successful trajectories for updates. Short budgets favor tasks solved quickly; longer budgets permit exploration and recovery but make outcome credit harder to assign. Its prompting experiments also show that repeated rechecking can replace a correct answer with an incorrect one. The useful question is consequently not whether longer thinking or more actions always wins, but which additional computation supplies relevant evidence under a fixed task, observation contract, and budget.

Systems choices can change the effective learning objective. AsyncWebRL overlaps rollout, training, and policy refresh through persistent workers and lightweight screenshot references. It separately corrects for stale rollout policies and studies how per-trajectory length normalization underweights tokens in long failed episodes. Replacing that normalization changes the relative influence of those failures. The reported diagnosis is tied to its WebGym setup, memory prompt, and model variants; it should not be generalized into a universal claim about all policy optimization. It nevertheless shows why efficiency analysis must inspect both wall-clock scheduling and the weighting of experience consumed by the learner.

Interaction cost and the execution environment

Fewer model calls can arise through different mechanisms. ActionEngine amortizes exploration into reusable operations and compiles a task program; its design still allows state filtering, repair, and explicit semantic helper calls. Qwen-UI-Agent can emit ordered action batches and combine GUI operations with CLI or service calls. Batching reduces observation and inference boundaries, whereas compilation reuses application knowledge. Both require care when later actions depend on an intermediate result. Reporting only action counts can obscure that difference: one model turn may contain several operations, and a programmatic action may perform work that would require many pointer events.

Branching adds another axis of computation: trying alternatives from the same workspace state. TClone provides local workspace versions using containers, copy-on-write sharing, and asynchronous checkpointing, including GUI state rather than only files. This supports rollback and speculative branches with an explicit commit boundary. Its network design also makes the limit clear: external connections must be re-established, and effects on remote services generally cannot be undone by restoring local state. Thus, cheaper search is not equivalent to harmless exploration. Any use of branching for computer control must distinguish reversible local operations from actions that affect other systems.

Mobile execution brings reset and failure accounting into the training design. Darwin Mobile Agent uses asynchronous cloud Android instances and a setup–execution–teardown lifecycle; minimal cleanup preserves some state between episodes, while infrastructure failures are distinguished from task termination. Its implemented system uses manually selected tasks, an external judge, and a configured history window. Internally learned curricula, verification, and memory remain roadmap goals. Qwen-UI-Agent similarly describes device-health scheduling and separate review of model and environment failures. Treating an unavailable service as an agent error, or silently removing such episodes, would change the learning and evaluation distribution.

Application knowledge and adaptation in recent mobile systems

Recent mobile work asks when an agent should acquire application knowledge rather than repeatedly improvise. Curiosity Driven Knowledge Retrieval compares predicted and observed interface descriptions, triggering retrieval into structured AppCards when its uncertainty signal rises. The cards summarize functions, parameters, interface mappings, and interaction patterns from documentation, code, and earlier trajectories. X-OmniClaw takes a complementary route: it combines Android XML, OCR, visual grounding, and multimodal context, then captures user behavior as reusable skill cards and activity or deeplink entry routes. Its “behavior cloning” describes skill capture at runtime, not demonstrated policy-weight training, and literal trace replay is presented as a future extension.

Adaptation also concerns the user and the stability of repeated workflows. PerPilot identifies missing personal information, retrieves it from accumulated memory, or explores a likely application before requesting clarification if information remains unavailable. This makes instruction interpretation part of control rather than assuming every goal is fully specified. AppCopilot describes a different reuse mechanism: semantic matching selects successful historical logs for direct replay under stable layouts and task structures. Its coordinate calibration moves out-of-region clicks toward detected widgets while remembering ineffective corrections. These mechanisms depend on the validity of stored information and detected regions. Reusing a preference, replaying a path, and correcting a coordinate therefore require different checks; none follows automatically from a high retrieval match.

Across these methods, generalization depends on what is retained and what can be checked. Visual grounding broadens interface access; application knowledge reduces repeated discovery; demonstrations and synthetic rollouts expand experience; outcome learning changes behavior under feedback. Each can also introduce a new dependency: perceptual errors, stale memory, collection bias, or an imperfect verifier. The strongest methodological reports expose those dependencies and distinguish local prediction, offline trajectory scoring, live completion, and infrastructure reliability. This makes progress interpretable without assuming that a larger model, a longer reasoning trace, or a higher score under a different protocol resolves the entire computer-use problem.
