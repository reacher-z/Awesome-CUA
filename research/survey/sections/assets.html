From literature lists to reusable research assets

A survey becomes more useful when a reader can move from an argument to the precise resource needed to investigate it. A paper may document several checkpoints, datasets, evaluators, or implementation components. Each can change independently. Accordingly, an actionable research collection needs identities, explicit relationships, source evidence, and a way to preserve uncertainty. Its design must serve researchers reading a comparison and software agents retrieving records for a later decision.

Documentation precedes aggregation

The FAIR principles connect discovery and reuse with persistent identifiers, rich metadata, standardized access, provenance, and explicit reuse terms. Their machine-oriented perspective is particularly relevant to retrieval systems that cannot safely reconstruct missing context from a title. FAIR4RS extends the discussion to research software and explicitly distinguishes component and version identities. These principles motivate our separation of a research work, its released artifacts, and observations about those artifacts.

Datasheets for Datasets organize documentation around a dataset's purpose, composition, collection, processing, uses, distribution, and maintenance, including cases where information remains unknown. Model Cards similarly connect a model's identity and intended use with evaluation data, relevant factors, metrics, and caveats. For computer-use research, these approaches encourage documenting the conditions behind a resource rather than treating an available download as a complete specification.

The AwesomeCUA snapshot as a worked example

The frozen inventory records 220 reviewed papers with explicit connections to 311 paper–asset pairs. These connections require relation-specific source evidence; incidental README mentions and shared topic labels do not qualify. The ratio describes what this catalog has connected. It is not an estimate of how many papers released code, and an unlinked paper should not be described as unreproducible. The same distinction applies to specification coverage: the snapshot contains structured profiles for 60 of its 83 benchmark resources and 66 of its 85 dataset resources. A missing catalog profile means that this collection has not recorded the protocol in that form.

The release illustrates why the unit of a claim matters. A repository can contain several components without making each component a new independent project. A model family can have several checkpoint releases with different availability or licensing. A paper can have both a preprint and a proceedings edition without becoming two studies. Keeping these identities separate permits a query about a training dataset or evaluation artifact to return a precise object, while relationships recover the broader research context. Identity resolution should therefore require affirmative evidence, rather than merge records solely because names resemble one another.

Evidence hashes are useful but have a limited role. They identify the bytes that were examined when those bytes are retained; they do not prove that an annotation is correct or that a mutable URL will still return the same response. A reliable update procedure must compare observations and reopen affected review decisions. Similarly, a successful HTTP request establishes accessibility of that response, not completeness of an implementation or permission to reuse every file. A paper's claims, the state of its code release, and reproduction by a third party should remain separately expressible.

A shared interface for people, RAG, and agents

Human navigation and machine retrieval should be generated from the same records. Human readers benefit from task-oriented paths, concise purpose statements, comparable specifications, and direct source links. Retrieval systems need stable identifiers, record boundaries, review states, citation URLs, and fingerprints. A useful retrieval-augmented generation (RAG) export carries the descriptive text together with the fields needed to qualify an answer. An agent can then retrieve a reviewed benchmark record, inspect its protocol, and cite the primary source instead of treating a search snippet as the complete evidence.

The frozen release packages 28 main exports and 105 exports across 35 overlapping topics, alongside manifests and guidance. Its reviewed and complete RAG exports have different populations; the complete export includes metadata-only records. Record identity, scope, and review state must survive indexing. Upserts should use canonical identifiers, and deletions should be reconciled against a complete snapshot rather than inferred from a partial search result. A retrieval experiment using this material should report its snapshot and selection policy so that a change in annotation coverage is not mistaken for a change in model quality.

Related collections can extend discovery without collapsing their scope into computer use. For example, Awesome-Jev organizes Jev and System One research, models, evaluation resources, and integrations around typed decisions. It is a useful neighboring entry point for studying bounded decision components. Individual interface applications, such as Jev-Mobile in the methods section, require their own primary evidence.

This design also clarifies what an “awesome list” can and cannot contribute. Its scientific value lies in reducing ambiguity about resources and making discovery and verification easier. The number of entries alone does not demonstrate search recall, balanced coverage, or correctness. Progress should be measured through auditable additions, resolved identity conflicts, richer protocol descriptions, and successful reuse of a fixed snapshot. Those outcomes are suitable targets for future usability and retrieval studies; they are not results asserted by the present descriptive analysis.
